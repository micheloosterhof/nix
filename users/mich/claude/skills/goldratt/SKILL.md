# Goldratt Thinking Processes

Five cause-and-effect tools answering three questions: what to change, what to
change to, and how to cause the change. They formalize reasoning already
performed when calm; their value is applying it reliably under pressure.

Each tool produces a required output. A tool whose output is not written down
was not applied.

## Tool Selection

| Situation | Tool |
|-----------|------|
| Multiple symptoms, or a recurring problem | Current Reality Tree |
| Requirements, principles, or stakeholders appear to conflict | Evaporating Cloud |
| Solution chosen but not yet executed | Future Reality Tree + Negative Branch Reservations |
| Goal clear, path unclear | Prerequisite Tree |
| Plan exists but steps feel underspecified | Transition Tree |

## 1. Current Reality Tree — what to change

Maps undesirable effects to the root causes that produce them.

**Procedure:** List the undesirable effects. Connect them with if-then
causality. Follow the chains downward until a small number of root causes
explains most of the effects.

**Output:** The causal chain with root causes identified. Act on root causes;
treat symptoms only as evidence.

## 2. Evaporating Cloud — what to change to

Dissolves an apparent conflict by invalidating the assumption that creates it.

**Procedure:** State the shared objective. State the two requirements serving
it. State the two prerequisites that conflict. Surface the assumption beneath
each requirement-prerequisite link. Attack the weakest assumption.

**Output:** The invalidated assumption and the action it unlocks. If no
assumption falls, the conflict is real — escalate per the Deadlock Protocol
(SOUL.md).

## 3. Future Reality Tree — what to change to

Projects the chosen solution forward to verify it produces the desired effects.

**Procedure:** Start from the proposed actions. Build the if-then chain to the
desired effects. Where a link is doubtful, add the supporting action that
firms it.

**Output:** The expected-effects chain from action to outcome.

### Negative Branch Reservations

For each proposed action, trace causal paths to adverse outcomes.

**Output:** Each negative branch with either a preventive action that trims it
or an explicit acceptance of the documented risk.

## 4. Prerequisite Tree — how to cause the change

Plans backward from the desired outcome.

**Procedure:** State the outcome. Identify the obstacles to it. For each
obstacle, define the intermediate objective that overcomes it. Sequence the
objectives by dependency.

**Output:** Ordered intermediate objectives, each paired with the obstacle it
overcomes.

## 5. Transition Tree — how to cause the change

Specifies implementation and exposes unverified assumptions.

**Procedure:** For each step, state the action, the current reality it acts
on, the need it addresses, and the expected result. A step that cannot be
explained this way is an unverified assumption.

**Output:** The step list with rationale, gaps flagged explicitly.

## Scrutiny: Categories of Legitimate Reservation

Challenge any tree with these tests before trusting it:

1. **Clarity** — is the statement unambiguous?
2. **Entity existence** — does the stated condition actually exist?
3. **Causality existence** — does the cause actually produce the effect?
4. **Cause insufficiency** — is the cause alone enough, or are contributing causes missing?
5. **Additional cause** — could a different cause produce the same effect?
6. **Cause-effect reversal** — are cause and effect swapped?
7. **Predicted effect existence** — if the cause is real, its other predicted effects should also be observable; are they?
8. **Tautology** — is the effect being offered as its own evidence?
